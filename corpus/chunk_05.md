## Canonical Source of Truth

### Current revision

This document consolidates the lessons learned from the Empirium, AI Staff Force and Hermes autonomous-software experiments, including the later discovery that **building an autonomy system is not the same thing as actually putting that autonomy system in control of the project**.

Where earlier ideas conflict with later findings, the later hardened methodology in this document takes precedence.

# 1. THE CENTRAL THESIS

The original ambition remains valid:

> Give an AI system a sufficiently detailed software objective, leave it running, and have it continue making useful progress until the software is genuinely finished.

But the architecture required to achieve that is very different from simply giving an LLM a huge prompt.

The first permanent lesson is:

> **You cannot turn an LLM into a reliable autonomous software company merely by giving it a sufficiently enormous prompt.**

The second, newer lesson is equally important:

> **Building the autonomy system is not the same as putting the autonomy system in control.**

An autonomy kernel can exist.

It can have a database.

It can implement WorkItems, Attempts, leases, retries and QA.

It can pass tests.

It can survive simulated worker death.

It can produce a commissioning report saying PASS.

And the real software project can still secretly depend on the Hermes or LLM session that launched everything.

SHIPPED
